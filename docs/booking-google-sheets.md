# Простая заявка → Google Таблица → Telegram

Гость заполняет **имя и телефон**, выбирает **заезд/выезд в календаре**, **номер** и при необходимости
отмечает **отчётные документы**. Количества гостей и комментария в форме больше нет.

Сайт отправляет заявку в веб-приложение Google Apps Script. Скрипт **сначала записывает строку в таблицу**,
затем через Telegram-бота отправляет модератору сообщение **«🌻 Новая заявка №…»** со всеми пятью полями.
Кнопки «✅ Подтвердить» / «❌ Отклонить» меняют скрытый статус заявки; подтверждённые брони на сегодня
по-прежнему отмечают номер как занятый на сайте.

> **Важно:** изменение `google-sheets/Code.gs` в GitHub не обновляет уже развёрнутый Apps Script.
> Чтобы применить новый формат к действующей Google Таблице, её владелец должен обновить код и
> развёртывание по шагам ниже. Ссылка `/exec` уже указана в `data/site.json` → `cfg.bookingApi`.

## Если таблица и бот уже подключены

1. Откройте действующую таблицу → **Расширения → Apps Script**.
2. До замены кода сохраните действующие настройки в **Настройки проекта → Свойства скрипта**:
   - `BOT_TOKEN` — действующий токен бота;
   - `MODERATOR_CHAT_ID` — chat_id модератора (несколько получателей через запятую);
   - `WEBHOOK_SECRET` — можно оставить пустым. Если прежний секрет был в открытом коде,
     удалите его из свойств: `setupTelegram()` создаст новый случайный секрет и обновит webhook.
   - Если в старом коде явно задавали `SHEET_ID`, сохраните этот ID в одноимённое свойство.
     Для скрипта, открытого из нужной таблицы, вручную указывать ID не обязательно.
   - Если лист назывался не «Брони», сохраните его имя в свойстве `SHEET_NAME`.
3. Замените **весь** `Code.gs` содержимым файла **`google-sheets/Code.gs`** из репозитория и сохраните.
4. **Развернуть → Управление развёртываниями → ✏️ Изменить → Новая версия → Развернуть**.
   Запуск — **от вашего имени**, доступ — **Все**. При обновлении существующего развёртывания URL `/exec`
   обычно остаётся прежним, и `data/site.json` менять не нужно. Сначала обновите развёртывание,
   чтобы старая версия не переписала новый формат при следующем запросе с сайта.
5. Выполните **`setup()`**. Скрипт создаст резервный лист **«Брони — архив …»** с исходными данными,
   перестроит рабочий лист и оставит только пять видимых колонок. Старые заявки, их номера, статусы,
   ref и связь с комнатами сохраняются. Гости/комментарии из прежней формы остаются в архиве,
   но не записываются в новые заявки. Если резервная копия не создалась, старый лист не меняется.
   Между обновлением развёртывания и `setup()` форма может временно показывать ошибку:
   публичные запросы сами не перестраивают старую таблицу.
6. Выполните **`setupTelegram()`**, чтобы кнопки модерации использовали актуальный webhook и секрет.
7. Откройте сайт → админ-панель → **«Проверить связь с таблицей и Telegram»**.
   Затем отправьте тестовую заявку и проверьте **строку в таблице и сообщение модератору**.

Повторный `setup()` не создаёт архив, если формат уже актуальный. Не удаляйте архив, пока не проверите перенос.
Не меняйте шапки скрытых колонок: по ним работают подтверждение доставки и кнопки модерации.

## Первое подключение

### 1. Таблица и скрипт

1. Создайте таблицу на <https://sheets.new> или используйте имеющуюся. Доступ к самой таблице
   оставьте **ограниченным**, только для сотрудников, работающих с заявками.
2. **Расширения → Apps Script** → замените заготовку кодом из **`google-sheets/Code.gs`**.
3. В **Настройки проекта → Свойства скрипта** добавьте:

| Свойство | Значение |
|---|---|
| `BOT_TOKEN` | токен бота из @BotFather |
| `MODERATOR_CHAT_ID` | chat_id модератора; несколько ID через запятую |
| `WEBHOOK_SECRET` | необязательно: `setupTelegram()` создаст случайный секрет |
| `SHEET_ID` | необязательно для скрипта внутри таблицы |
| `SHEET_NAME` | необязательно: имя листа, по умолчанию «Брони» |

В коде оставлен прежний chat_id `7114829971` как значение по умолчанию. Для другого получателя
задайте `MODERATOR_CHAT_ID` в свойствах. Пустое свойство отключает отправку уведомлений.

Модератор должен открыть чат с ботом и нажать **Start**: бот не может первым начать личную переписку.
Токен получают у @BotFather, личный chat_id — у @userinfobot.

> **Безопасность:** старый токен ранее был опубликован в файлах сайта и истории GitHub.
> Если вы всё ещё используете его, отзовите через @BotFather → `/mybots` → ваш бот → *API Token* →
> *Revoke current token*. Новый токен сохраняйте только в свойствах Apps Script.
> Не отправляйте его в чат, не добавляйте в `data/site.json`, JavaScript сайта или Git.

### 2. Подготовка листа

Запустите **`setup()`** в редакторе Apps Script. Разрешите доступ к таблице и внешним запросам.
Лист «Брони», шапка, текстовый формат телефона и скрытые служебные поля создаются автоматически.
Скрипт сохранит ID таблицы в свойствах, чтобы веб-приложение могло открывать её вне редактора.

Часовой пояс таблицы и уведомлений — `Europe/Moscow`.

### 3. Развёртывание

**Развернуть → Новое развёртывание → Веб-приложение**:

- **Запуск от имени: Я**;
- **У кого есть доступ: Все** (анонимные гости сайта должны иметь возможность отправлять заявку).

Скопируйте URL, заканчивающийся на `/exec`. Публичен только приём заявок, а не доступ к самой таблице.
Затем выполните **`setupTelegram()`**. Уведомления о новых заявках отправляются и без webhook;
webhook нужен для кнопок «Подтвердить/Отклонить» и команд бота.

### 4. Ссылка на сайте

Укажите URL `/exec` в `data/site.json` → `cfg.bookingApi`. Это настройка **для всех посетителей**.
Или задайте его в админ-панели сайта в поле **«📊 Google-таблица броней»** и примените общие настройки.
Обычное локальное сохранение в админ-панели меняет настройку только в текущем браузере.

Адрес уже настроенного веб-приложения менять не нужно, если вы обновляете его существующее развёртывание.

## Как выглядит рабочая таблица

Видимы **только данные из формы**:

| Имя | Телефон | Заезд/выезд | Номер комнаты | Отчётные документы |
|---|---|---|---|---|
| Анна | +7 918 000-00-00 | 12.10.2026 – 14.10.2026 | Номер 3 | Да |

Номер телефона хранится текстом, чтобы не потерять `+` и ведущие нули.
Документы — **Да** / **Нет**, в зависимости от галочки.

Пять служебных колонок **скрыты**: `№заявки`, `Дата заявки`, `Статус`, `Ref`, `RoomId`.
Они нужны для дедупликации, подтверждения доставки, кнопок модерации и статусов номеров.
В них нет дополнительных сведений, запрашиваемых у гостя. Их можно показать через меню столбцов,
например для ручного изменения статуса.

В новом рабочем листе нет колонок с количеством гостей, комментарием, источником или числом ночей.
Количество ночей для уведомления рассчитывается из дат и отдельно не хранится.

## Сообщение модератору

```text
🌻 Новая заявка №1
🕒 Дата заявки: 12.10.2026 10:30
👤 Имя: Анна
📞 Телефон: +7 918 000-00-00
📅 Заезд/выезд: 12.10.2026 – 14.10.2026 — 2 сут.
🛏 Номер комнаты: Номер 3
📄 Отчётные документы: Да (нужны)

Статус в таблице: Новая
[✅ Подтвердить] [❌ Отклонить]
[📊 Открыть таблицу]
```

После подтверждения данные гостя остаются в сообщении. Бот принимает кнопки и команды только
с секретом webhook и от настроенных модераторов.

Команды: `/start` (справка), `/status` (номера, занятые сегодня), `/today` (новые заявки за день).

## Проверка и обработка ошибок

- Сайт показывает успех **только после записи в таблицу**: ответ с номером заявки или `action=verify`.
- Если ответ POST потерялся, сайт проверяет запись по случайному `ref`.
- Повторная отправка одного `ref` или одинаковых пяти полей в течение 15 минут не создаёт дубль.
  Изменение даты выезда, номера или необходимости документов считается другой заявкой.
- Имя, телефон, обе даты и номер проверяются и в браузере, и на сервере; скрытая ловушка отсекает ботов.
- Если Telegram недоступен, строка **не теряется**, но возвращается `notified: false`.
  Гость увидит предупреждение и телефон для быстрой связи. Проверяйте новые строки в таблице:
  автоматической фоновой повторной отправки уведомлений нет.
- «Бот на связи» в `testConnection()` означает успешный `getMe`, а не гарантированную доставку в чат.
  Полную проверку даёт только тестовая заявка.
- Публичный `ping` нового скрипта возвращает `schemaVersion: 2` и список пяти видимых полей;
  если версия старая, админ-панель напомнит обновить Apps Script.

| Проблема | Что проверить |
|---|---|
| Форма приняла заявку, но таблица всё ещё старого формата | Обновите `Code.gs` **в Google Apps Script**, выполните `setup()` и разверните **новую версию**, не только файлы сайта. |
| Строки нет и сайт показывает ошибку | URL заканчивается на `/exec`, веб-приложение запускается от владельца и доступно **всем**; у владельца есть права на таблицу. |
| Строка есть, Telegram не получил сообщение | `BOT_TOKEN`, `MODERATOR_CHAT_ID`, не заблокирован ли бот, нажал ли модератор **Start**. |
| Кнопки не работают | Выполните `setupTelegram()` после обновления развёртывания или секрета. |
| Номер не отмечен занятым | Статус **Подтверждена** или **Заселена**, даты покрывают сегодняшний день в Москве, `RoomId` заполнен. |

## Локальная проверка без Google и Telegram

```bash
node google-sheets/tests/backend.test.js
node demo/serve.js
```

Демо: `http://localhost:4173/rooms.html`. Заявки записываются в локальную мок-таблицу;
на `http://localhost:4173/demo/sheet` видны пять полей и предпросмотр сообщения модератору.
Это **не** настоящая таблица и **не** отправка в Telegram.

Для проверки уже развёрнутого веб-приложения:

```bash
LIVE=1 node demo/serve.js
```

Откройте `/selftest`: «Проверить связь», затем «Отправить тестовую заявку».
Во втором случае **действительно** создаётся строка в рабочей таблице и уведомление модератору.
После проверки удалите тестовую строку и сообщение. Запросы идут из вашего браузера, как у гостя сайта.
